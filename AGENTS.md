# Repository Guidelines

## Scope

MWU is a generic UI for [MaaFramework](https://github.com/MaaXYZ/MaaFramework), used by one person locally or on a trusted LAN; it is not a multi-user service. Users supply `resource/`, `interface.json`, and `agent/`: improve the generic loader/runtime, never bake in project-specific behavior.

Write the simplest correct implementation and keep the backend/frontend API contract. No accounts, tenancy, distributed coordination, generic frameworks, compatibility layers, or speculative abstractions. Keep safeguards only for real failure modes (malformed config, unsafe paths, interrupted writes, cancellation, subprocess cleanup, overlapping runs, background threads). Validate at the boundary and surface failures; no re-validation of normalized data, blanket exception suppression, silent fallbacks, or unjustified retries.

## Layout

- Backend: `main.py` (CLI: args, single-instance check, native-dispatch delegation, `uvicorn.run`); `backend/runtime.py` (app root, interface/language loading, `AppState`); `backend/app.py` (FastAPI assembly, lifespan, static/SPA, routers); `backend/api/` (domain routers); `backend/core/` (paths, state, settings IO, secrets, JSON); `backend/maa_worker/` (`execution.py` run lifecycle, `worker.py` composition, MAA services, sink/focus); `backend/scheduler/`; `backend/services/` (update, telemetry, notification, log export); `backend/models/` (Pydantic, interface/task-config normalization).
- Frontend `front/src/`: `app/` (bootstrap, router, i18n, theme), thin `views/`, domain `components/` (shared in `common/`), Pinia `stores/`, `services/` (api/feedback/realtime), `validation/`, `types/`, `utils/`. Vite builds to `page/`.
- `.github/workflows/`: MWU's own CI/release. `updater/`: Go updater. `deploy/`: templates for downstream projects consuming an MWU release; `deploy/install.yml` replaces MaaPracticeBoilerplate's `install.yml` (flattens `assets/`, `agent/`, `README.md`, `LICENSE` onto an MWU release; assets `<repo>-<os>-<arch>-<tag>.7z`).

## Architecture

- **Hosting**: `APP_ROOT_DIR` holds `page/`, `config/`, `agent/`, `deps/` and is the MAA toolkit/agent cwd; `PROJECT_DIR` holds `interface.json` and resolves all PI-relative paths. Packaged, both are the executable dir; from source the project dir is `assets/` (gitignored test data). Lifespan builds `MaaWorker`, broadcaster, history store, `SystemScheduler`, `SchedulerManager`, converging native registrations while APScheduler is paused. Uvicorn binds `0.0.0.0:5566`; browser launch and delegation use loopback. `/assets` → `page/assets`, `/resource` → project `resource/`, SPA fallback `page/index.html`. `/api/file` and `/api/file/list` (one level) accept only project-contained paths: leading `./` dropped; `..`, empty segments, absolute/drive paths rejected; symlinks escaping the project are omitted.
- **State/DI**: `AppState` (`backend/core/state.py`, with `WorkerContext`, pending modals, `ActiveRun`) owns broadcaster/history, settings, device/task/agent/focus state, the `active_run` slot, update gate, scheduler refs, shutdown. `MaaWorker` is a DI container: module-level CPU `Resource`, per-runtime `Tasker` and HTTP client, and services `events`/`focus`/`device`/`pipeline`/`agents`/`pretasks`/`tasks`/`sinks`/`text` that collaborate via the worker back-reference.
- **Persistence**: settings/task-config writes encrypt, then `atomic_write_json` (tmp+fsync+replace under `SETTINGS_LOCK`); a failed save keeps the old file. `/api/settings` POST preserves `panel.customDevices`. `password` inputs are Fernet-encrypted at rest (`secret_store.py`, key in the per-user data dir) in `settings.json`, `task_config.json`, and APS job kwargs; plaintext in memory and API responses. APS jobs and history share `config/scheduler.sqlite`.
- **Package**: `page/` + Nuitka standalone backend + MaaAgentBinary + Go updater.

### Execution

- **Pipeline**: manual, in-app scheduled, and native scheduled starts all go through `execution.py`. `_complete_run`: admit into the single slot → normalize payload (≥1 valid task before any command) → interface `pretask` executables (no timeout, only stop ends them) → user `PreTaskCommand` shell commands (configured timeout) → prepare device/resource (skipped when reusing a locked connection) → `TaskService` → history → clear slot. Pre-task failure aborts. `PretaskService` owns capture, timeout, stop polling, termination.
- **Keep awake**: runs execute inside wakepy `keep.running` (`_run_keep_awake`), blocking sleep but not screen-off; activation failure is logged and ignored. Enter/exit stay in the event-loop coroutine (not thread-safe). `keep_awake.py` patches wakepy 1.0.0's Windows method so a failed activation releases its non-daemon inhibitor thread.
- **Stop**: `_claim_slot` resets `stop_flag` on admission only; resetting later loses stops. `run_process()` polls stop before/during/after tasks; `PretaskService` polls during subprocesses. Cancelling during pre-tasks must drain the shielded pre-task future before clearing `active_run`.
- **Terminal events**: `run_process()` emits none. `_complete_run` emits `task.completed`/`task.failed` after history; slot clearing and `publish_task_terminal` share one synchronous segment (no `await`), so a new `task.started` cannot precede it. Notifications follow on a worker thread; the subject uses the label captured at start.
- **`configuration_locked`**: set when `set_resource()` succeeds after connect; locked `connect()`/`set_resource()` refuse while the connection lives. `reset_connection_state()` releases it on connection/liveness/screencap failure or when execution replaces an incompatible connection.
- **Agents**: lazy one-shot start via `ensure_started_once()` in `TaskService.start()`; `started_once` ratchets on failure, and already-connected external processes are cleaned up before the aggregate error is kept. Embedded Python agents (`agent_loader.py`) use a custom finder, `deps/` precedence, the `_BlackMagicAgentServer` client-mode stub, regex/AST registration, and in-process instances; external agents use `AgentClient` + subprocesses. The decorator regex only matches `@AgentServer.custom_action("...")`/`custom_recognition("...")` with double quotes and the `class` line directly below; anything else fails silently.
- **Task identity**: execution and option maps key on unique `task.name`, not `task.entry` (which may repeat and is resolved only at `post_task`). Repeated names share one option map and run in order; UI uses per-entry `uid` (regenerated, not persisted). `active_run.task_name` is only a display label.

### Interface and options

- **Loader** (`interface_loader.py`): imported fragments may contain only `task`/`option`/`preset`/`pretask`/`import`/`global_option`/`setting`, resolved from the app root. Duplicate tasks/presets and path escapes fail loudly; later option keys override; groups dedupe by name (first wins). Post-merge validation covers references, presets, pre-tasks, settings, and duplicate case/input/hotkey names. `scan_select` expands `scan_dir` + `scan_filter` into in-memory cases; rescan via `/api/interface/scan-select/rescan` under `interface_lock`.
- **Overrides** (`PipelineOverrideService`): task `pipeline_override`, then deep-merge `global_option` → resource → controller → task options, including recursive cases, applicability, input coercion, placeholders, and `scan_select`. Hotkeys convert per controller (`hotkey.py`). Omitted option `type` serializes as `select`.
- **Global values**: `interface.setting` only groups UI. Its values and PI `pretask.option` values (edited inline in `PreTaskList.vue`) persist in `settings.json.globalOptionValues`; only `global_option` members enter overrides.
- **Path inputs**: `input_type` `file`/`directory` (requires `pipeline_type` `string`) render a text box plus `ProjectPathPickerDialog.vue` (lazy `/api/file/list`, `.` = project dir), the LAN-safe stand-in for PI's system dialog. Values are stored project-relative; `InputCase.runtime_value` makes them absolute under `PROJECT_DIR` for overrides and pretask payloads. Absolute or empty values pass through; existence is not checked.
- **Pre-task enabled state**: `settings.json.pretaskEnabled`, keyed by `name` or compact JSON `[exec, ...args]` (byte-identical between `Pretask.key` and frontend `pretaskKey`; duplicates rejected; missing = enabled). Rewritten on switching/resetting to a preset declaring `pretask` (unlisted → unchecked) or on load when empty, so `App.vue` loads settings before `loadConfig()`. Manual start awaits `flushSaves` and aborts if saving fails, because execution reads saved settings. `preset.controller` only filters presets in the UI.
- **Task config** (`config/task_config.json`): `selectedPreset` + per-preset `tasks`/`taskOptions`/`preTasks`. Normalization seeds missing presets, drops invalid names keeping order/repeats, normalizes options, and never appends tasks to an existing queue.
- **`$key` text**: `interface_text.py` and `resolveInterfaceText` resolve against `settings.json.ui.language` (mapped to `interface.languages` keys), flat key then dotted path; missing → `None`/caller fallback, never literal `$key`. `resolve_tree` keeps originals for PI env payloads. `ui.language` is authoritative; the store backfills from the `locale` cache only when it is `null`.
- **Custom devices**: validated/canonicalized by `device_address.py` + `validation/device.ts` (strict custom, lenient scanned Adb), stored in `panel.customDevices`; scan wins on duplicates.

### Events

- **Bridge**: MAA threads push `RealtimeEvent` into `AppState.message_conn` (`SimpleQueue`, 0.05s throttle); `log_monitor` polls every 100ms, records non-modal events in bounded history, and fans out via `LogBroadcaster` to SSE `/api/logs` (if it dies, SSE goes silent). Event names live in `backend/models/api.py`; adding one also updates `front/src/types/realtimeModel.ts`, listeners in `front/src/app/main.ts`, and dispatcher/SSE normalization as needed.
- **Sink→Focus**: built-in sinks flow `SinkHandler` → `UnifiedFocusResolver` → `FocusEventProcessor`. `log`/`toast`/`notification`/`dialog` map to `focus.display`; `notification` may also fire system and external notifications, with policy re-read from persisted `settings.json`. Agent EventSink subclasses are AST-detected and registered directly on MAA objects, bypassing focus.
- **External channels**: `notification.channels` is a `type`-discriminated list (`models/notification.py` ↔ `settings/notification/channels.ts`). `services/notification.py` instantiates apprise plugin classes directly, never URLs (URL discovery needs a plugin directory absent under Nuitka). DingTalk/Feishu/WeCom and custom webhook are local `NotifyBase` subclasses (apprise ignores 200-with-error-code bodies; its Feishu lacks signing). `app_id` stays ASCII `MWU` (used in headers). Sends run on a daemon thread; failures are logged as status code/exception type only (URLs hold tokens), never raised. With `attachScreenshot`, the send thread grabs a JPEG via `capture_notification_jpeg()` (none when disconnected; waits at most 10s; failure only logs and never resets the connection, unlike `get_screencap_bytes()`) and passes it as an in-memory apprise attachment: SMTP/Telegram/OneBot natively, WeCom as a follow-up image message (re-encoded down to its 2 MB limit), webhook via `{{screenshot}}` Base64 (the default body adds a `screenshot` field only when attached); other channels send text only.
- **Notification triggers**: each `notifyOn*` setting (`NotificationTrigger` ↔ frontend type) gates one point via `EventService.notify(trigger, ...)`, which re-reads settings and always logs; only the push is gated. Points: run start (`task.started`), per-task success/failure in `run_process` (skipped on stop), pre-task failure (not on user stop, including a stop that kills the child between polls), connect failure after all retries in `_complete_run` and on manual `POST /api/device`, scheduled skip on a run conflict in `submit_scheduled` (not update-in-progress), scheduler errors (`notifyOnError`). Whole-run complete/error stay in `publish_task_terminal` using pre-read settings. `DeviceService.connect()` itself sends no notification, so retries do not repeat it.
- **Blocking modals**: `FocusEventProcessor` blocks the sink callback until `POST /api/focus/{id}/confirm` or cancellation. `focus.modal` carries the full pending snapshot, skips history, replays on SSE connect, and has an intentionally empty `message`. `TaskService.stop()` sets `stop_flag` under the focus lock, then releases pending modals; keep that order. It is a confirmation gate, not pause/resume.

### Scheduling

- **APScheduler 3**: `AsyncIOScheduler` + `SQLAlchemyJobStore`. `scheduled_job_fired` must stay module-level in `scheduler/manager.py` (persisted reference); `_CALLBACK_STATE` is bound in `initialize()`. Conflicts `busy_manual`/`busy_scheduled`/`update_in_progress`: manual rejections write no history, scheduled skips do. SQLite work runs via `asyncio.to_thread`, finalization is shielded, pre-start cancellation is compensated, `scheduler_executions` keeps 1000 rows.
- **Native wakeup**: `SystemScheduler` is a stateless desired-set adapter over `schtasks`/`launchctl`/`crontab`/`NullBackend`, with list-arg subprocesses and platform quoting. Converge re-registers enabled tasks, removes orphans, isolates per-task failures, and reports listing failure as `ConvergeReport.list_error` (backends raise rather than return empty). Create: native first, unregister if APS fails. Update: APS then native (raises; startup converge repairs). Delete/pause/resume return `False` only for a missing job. Startup registration failures degrade to in-app dispatch. `--scheduled-task <id>` delegates to a running instance via loopback, else runs with origin `native`.
- **Cron subset**: `PortableCronStr` (wraps `CronStr`): 5 fields, single value or `*`, concrete minute, no day+DOW combo; feeds both APScheduler and OS conversion. `validation/cron.ts` mirrors it and gates the wakeup switch; both share `tests/fixtures/validation_contract.json`. Same-minute native conflicts are blocked on create/update.

### Update, version, telemetry

- **Update**: `update_service.check_update()` returns an `UpdatePlan` (`models/update.py`) comparing `interface.version`; MirrorChyan first, its URL used when present (`update_type` incremental → `incremental`), otherwise GitHub release with the same tag; without MirrorChyan, GitHub `latest` (stable) or newest release (beta). Only the newest of overlapping checks is stored. GitHub assets from `deploy/install.yml`: full `<name>-<os>-<arch>-<tag>.7z`, resource `<name>-resource-<os>.<arch>-<tag>.7z` (`.` keeps older clients matching `<os>-<arch>` off it), `mwu-release.json` `{version, mwu_version}`. Resource package only when the release's `mwu_version` equals the local `mwu-install.json` (`core/install_manifest.py`, written by `deploy/package.py`: `client`/`resource` file lists; a resource overriding a client file is listed in both, which forces full; unreadable manifest = none) and no resource overrides a client file; otherwise full. Proxy applies to non-MirrorChyan sources; SHA-256 verified when given. Downloads go to fixed `update_package` (remote names never used). `update_in_progress` is checked and set before the first `await` (overlapping `/api/update` rejected) and gates admission; cleared on download/outer failure or in the updater-loop `finally`; success shuts the process down. `mwu-updater -type full|resource|incremental` (required): guarded extraction, exit-code-10 self-update, webhook shutdown, lock wait, recovery of a previous `update_backup/` (committed → discard, else restore; failure aborts), plan (`apply.go`: paths checked lexically and against symlink/junction components before any read; full copies the package and deletes files dropped from the old manifest, none without one; resource requires matching manifests' `mwu_version` and no overrides; incremental follows `changes.json`, `deleted_dir` only removes dirs left empty), transactional apply (delete, prune, mkdir, copy, manifest last; `created.json` journal written first, replaced files in `update_backup/files/`, `committed` marker before cleanup), rollback + restart old on failure, detached restart.
- **Version**: root `version` is a gitignored, possibly stale artifact; release writes `github.ref_name` to `build/main.dist/version`. `build_pi_env()` reads it into `PI_CLIENT_VERSION` (empty if missing) and sets `PI_USER_DATA_DIR` to the app root.
- **Telemetry**: `services/telemetry.py` is the only `sentry_sdk` importer. Enabled only with `interface.telemetry.sentry.dsn`, a Nuitka build (`__compiled__` or `MWU_TELEMETRY_FORCE=1`), a non-debug resource version, and `telemetry.helpImproveSoftware` (default true, applied on settings POST); init failure logs and disables. One `RunTrace` per run, `finish()` after history and before slot clearing; per-task spans carry redacted option summaries. Failed runs send one event tagged `failure.stage`; task failures attach `on_error` screenshots and the `maafw.log` tail, `pretask`/`device` failures send only the stage. Focus templates with `trace` (default `Node.PipelineNode.Failed`) add `mwu.node` spans. Logging is breadcrumb-only, excluding `backend.maa_worker.execution`.

### Frontend

- `main.ts` installs Pinia/router/i18n, anchors naive-ui styles, registers SSE listeners before mount. `App.vue` provides config/message/dialog providers, hosts `FeedbackBridge` (must stay under `NMessageProvider`) and `FocusDialogHost`, hydrates interface/task config/settings, owns navbar/dock/update UI. `AppMain.vue` uses `<router-view>` `mode="out-in"`; keep each view inside one keyed `<div>` (multi-root breaks routing). Home is eager, other routes lazy.
- API modules use raw `fetch()` with their own mapping/feedback; `services/api/core/types.ts` shares only envelope types. `SSEClient` does a minimal shape check and reopens only after native `EventSource` reports `CLOSED`.
- Stores: settings serializes whole-document saves via a queue; task-config owns queue/options/presets with debounced saves, trusts server normalization, and never persists after a failed load; `focus/focus.ts` owns the dialog queue, blocking modals first.
- `stopActiveAndRestart` (`stores/device/deviceConnection.ts`) stops, waits (bounded) for `TaskRunning` to clear, then retries `busy_manual` every 500ms up to 60s (`/api/stop` returns before `active_run` clears). It never retries other conflicts, shares one in-flight sequence, and is cancelled by `cleanup()`.
- `TaskSelectList` keeps `:delay="120" :delay-on-touch-only="true"`. `SchedulerTaskDialog` enables wakeup only for eligible cron.
- **Log export** (`/api/logs/export`, `services/log_export.py`): zip of SSE history (`mwu.log`), line-aligned tails of `debug/*.log` and `updater.log`, and newest `debug/on_error`/`debug/vision` images within a size budget. Plaintext `password` values (including JSON-escaped) are masked, collected from settings, all presets, scheduled jobs, and `AppState.run_secrets` (added by `_complete_run` before pre-tasks, kept until restart). Text logs are snapshotted before collecting passwords.
- **Screenshot/tap**: save/copy uses lossless PNG `/api/device/screenshot` at the controller's capture size (the frame tasks see; raw size would change a shared option mid-run). Clipboard copy needs a secure context, so plain-HTTP LAN shows an error. Tap mode maps `object-contain` preview clicks to pixels (`utils/containedPoint.ts`) and posts `/api/device/click`; a failed click on a dead connection releases the lock.

## Commands

- Backend: `uv sync` (Python >=3.13); `uv run main.py` (no `--reload`); `uv run pytest tests/ -q`; `uv run ruff check .` / `uv run ruff format .`.
- Frontend (`cd front`, pnpm 11, Node >=24.13.0): `pnpm install --frozen-lockfile`, `pnpm dev` (proxies `/api` to `:5566`), `pnpm build` (to `../page`), `pnpm lint` (oxlint + eslint), `pnpm format` (oxfmt), `pnpm type-check`, `pnpm test:run` (Vitest, jsdom + MSW).
- Updater: `cd updater && go build`. Nuitka deps: `uv sync --locked --group build`; build steps in `.github/workflows/build.yml` and `README.md`.
- `uvx pre-commit run --all-files` (needs frontend deps); commit hooks format staged files only.

## Coding Style

- One cohesive responsibility per file, ideally under ~800 lines; split by responsibility, not line count, without tiny-module sprawl. Small public APIs, no circular deps, no unrelated refactors.
- Python 3.13+, snake_case, modern syntax (`list[T]`, `X | None`, `type`); no version checks or shims.
- Frontend: 2-space, LF, 100 cols, double quotes, no semicolons; Tailwind v4 with naive-ui. Lint forbids `as`, enums, `else`, `try/catch` (use literal unions, early returns, `utils/tryCatch.ts`), raw `fetch` outside `services/api` and `utils/interface/content.ts`, `useMessage` outside `FeedbackBridge.vue`, and `@/stores` barrel imports inside `stores/`.
- Lint split: oxlint (`.oxlintrc.json`, type-aware for `.ts`) owns every rule it implements; `eslint.config.ts` disables those via `eslint-plugin-oxlint`, keeps typed rules for `.vue`, and adds Vue/vue-i18n/style rules. Inside `withVueTs()`, scope typed rules with `files`, never `ignores`.
- Vue APIs and naive-ui template components are auto-imported; import explicitly only values used outside templates and types. Never hand-edit `front/auto-imports.d.ts` or `front/components.d.ts`.
- User-facing text goes in mirrored zh-CN/en-US dictionaries.
- Respect pnpm `catalog:` and lock files; check current official docs before adding or changing third-party library usage.

## Testing

Backend tests in `tests/unit/` (fixtures `tests/conftest.py`); Vitest tests colocated in `front/src/`, shared MSW/EventSource setup in `front/src/tests/`. CI runs ruff, pytest, Vitest, type-check; lint/format are local.

Keep tests minimal and behavioral: extend existing ones, add cases only for plausible user-visible bugs or real contract/boundary/state transitions, delete tests for removed behavior. Never assert source text, exact wording, call wiring, or mock forwarding.

Verify proportionally: backend → focused pytest plus `uv run main.py` or `import main` smoke; frontend → build/lint/type-check, relevant Vitest, and headless Chrome smoke (`--headless=new --disable-extensions`); updater → `go build` plus a focused scenario. Doc-only edits need no runs.

## Commits & PRs

Conventional Commits (rules in `.github/.copilot-commit-message-instructions.md`), short subjects, no trailing period. PRs describe the change, list validation, link issues, and include screenshots for visible frontend changes.

## AI Assistant Practices

- Use `task` subagents (`scout` for read-only research) for independent slices; the main agent owns decomposition and cross-task contracts.
- Check project memory/history before substantial changes and verify against current code. Never write intermediate status, investigation reports, or planning docs into the repo unless asked.
